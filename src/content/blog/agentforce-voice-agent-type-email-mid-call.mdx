Have you ever tried to spell your email address to a voice agent? "C as in cat, H, R..." and then it reads back something completely different. Email addresses, name spellings and booking codes are some of the hardest things for a voice agent to hear correctly.

**Typeback** is a pattern I built for Agentforce Voice to fix that: when the caller wants something emailed, the agent makes a link to a one-field form instead of asking them to spell it. The caller types the email on their phone, says "done", and the agent reads back a masked hint ("starting with C, at example dot com") on the same call. The agent's language model never sees the full email.

In this tutorial I'll walk you through every step to rebuild it in your own Salesforce org, in order, plus every problem I hit along the way and how I fixed it. You can follow it by hand, or hand it to an AI coding agent and do only the steps that need a person.

## TL;DR

- You'll build a phone number that reaches an Agentforce Voice agent (a resort concierge) that captures the caller's email through a form link instead of speech.
- The code (Apex, a Lightning Web Component form, an Agent Script agent and setup scripts) is in the [agentforce-typeback GitHub repo](https://github.com/ProstDev/agentforce-typeback). Most steps are one script.
- The Setup click paths (site activation, phone number, Omni-Channel flow, voice channel) have to be done by a person.
- The full loop works on a live call from a mobile phone. What's not done: texting the link automatically. For now the link reaches the phone by hand.
- Every gotcha I hit is in the [troubleshooting tables](#troubleshooting-every-problem-i-hit-and-the-fix) at the end.

## What you'll build

Here's how a call flows from the caller's phone to the agent and back, one step at a time:

1. **The call reaches the agent.** The caller dials the phone number. An Omni-Channel flow with a single **Route Work** element sends the call to `TypebackDemoVoice`, the Agent Script agent.
1. **The caller asks for an email.** For example: "Can you email me my booking confirmation?"
1. **The agent makes a link.** `TypebackRequestAction` creates a random token and saves only its hash on a new `Typeback_Request__c` record with the status **Pending**. Then it hands the link to the sender.
1. **The link reaches the caller's phone.** For now, the Log sender saves the link on the record (`Test_Link__c`) and `scripts/link.sh` prints it so you can open it by hand. An SMS sender would text it at this step instead.
1. **The caller types their email.** They open `https://<site>/typeback/?t=<token>`, which loads the `typebackForm` Lightning Web Component on a guest site. `TypebackFormController` saves the email and sets the record to **Submitted**.
1. **The caller says "done".** At the start of that turn, a router guard runs `TypebackCheckAction` before any LLM pass.
1. **The agent reads back a masked hint.** "I have an email starting with C, at example dot com. Is that right?"

### The design rules

These are the rules that make it work. Keep them in mind if you change the code:

- **The agent actions never throw and never return nulls.** Every Typeback line the agent says is written in Apex and spoken word for word.
- **Only the token's SHA-256 hash is stored.** The link carries a 128-bit random token, so a record can't be used to rebuild its link.
- **The agent user can't read the typed value.** The `Typeback_Agent` permission set has no access to `Value__c`, and an Apex test proves it.
- **Send before saving.** Apex can't make a callout after DML in the same transaction.
- **Links are tied to their call.** The call Id comes from the agent's `VoiceCallId` linked variable, never from what the caller says.
- **Pull, not push.** There's no API to push an event into a live voice session, so the agent checks for the typed value on the caller's next utterance.

**Handing it to an AI coding agent?** Give it this page and a prompt like: *"Follow this tutorial from Phase 0. Run the [AI] steps yourself. At each [HUMAN] step, stop, tell me exactly what to do, and wait until I say it's done."* Also give it the rules below.

### Rules for an AI agent

1. **Stop at every [HUMAN] step.** Say what to click, then wait. Don't look for a scripted way around it.
1. **Never do these without the person's go-ahead at that moment:** activate a site, get a phone number, register an SMS brand or campaign, send an email or SMS (even to the person), or delete anything in the org.
1. **Keep secrets out of output.** `sf org display` prints an access token, so use `--json` with `jq` and pick out only the fields you need. Never print tokens, session IDs or login URLs. Show phone numbers as their last four digits only.
1. **Keep org details out of committed files:** usernames, org IDs, domains and phone numbers. `.env.local` and `org-reference/` are gitignored, so those details can go there.
1. **Before any commit, put the agent user placeholder back:** `node scripts/setup-agent-user.js --username __AGENT_USER_PLACEHOLDER__`
1. **Live form links are bearer links.** Don't paste one anywhere public. It works until it's used or it expires.
1. **Run scripts by path,** for example `/bin/bash scripts/report.sh`. Each one moves to the repo root and reads `.env.local` itself. Pass `--json` to `sf` commands in non-interactive shells, because their progress display floods logs otherwise.
1. **Describe before you query.** Some fields you'd expect aren't queryable (for example `MessagingChannel.SessionHandlerType` and `VoiceCall.IsVoiceMail`). Check with `sf sobject describe -o typeback -s <Object> --json | jq -r '.result.fields[].name'`.

**The Salesforce org** needs all of these (Phase 0 checks them):

- Agentforce, with Agentforce Service Agents

### How the agent works

If you want to change the agent, here's the shape of `TypebackDemoVoice.agent`:

- **A router guard runs first on every turn.** It clears `tb_line` first. Then, if a link is out (`tb_waiting`), it runs the check action and goes straight to the `email_capture` subagent, with no LLM routing pass.
- **`email_capture` makes the link on entry,** without the LLM, then says `tb_line` word for word.
- **Its tools are gated with `available when` on `tb_status`:** `send_to_number`, `resend_link`, `skip_email` and `confirm_email`.
- **The resort facts live in the system instructions** (check-in, spa hours and so on). They're made up for the demo.

This is the router guard. It's the part that makes the pull model work:

```text title="TypebackDemoVoice.agent"
start_agent agent_router:
   reasoning:
      instructions:->
         set @variables.tb_line = ""
         # A link is out: check it and go straight to email_capture, with no routing pass.
         if @variables.tb_waiting:
            run @actions.router_check
               with voiceCallId=@variables.VoiceCallId
               with requestId=@variables.tb_request_id
               with cancel=False
               set @variables.tb_status = @outputs.status
               set @variables.tb_hint = @outputs.spokenHint
               set @variables.tb_line = @outputs.agentLine
               set @variables.tb_waiting = @outputs.waiting
            transition to @subagent.email_capture
```

## Phase 4: Route a phone number to the agent

The agent must be active (Phase 3) before you start, so it shows up in the routing picker. I did all of this in Setup. Deploying the flow as metadata wasn't tried.

**4.1 [HUMAN] Get a number.** Go to **Setup → Agentforce Voice Setup → Voice Channels with Agents → New Number**. A wizard opens in a new window:

1. Pick a country.
1. Number type: **10-Digit Long Code**.
1. Pick a number.
1. Click **Review & Save**, then **Finish**.

The number shows as Requested, then Live within minutes. Use the Phone Numbers tab's **Refresh Status** to check. Mine was free because of the org's entitlement. If your org has none, check with whoever owns the org's contract before you go ahead.

**4.2 [HUMAN] Build the routing flow.** Go to **Setup → Flows → New Flow → Omni-Channel Flow**.

1. The flow needs a Text variable named `recordId`, available for input. Salesforce passes the VoiceCall Id in it. Create it if the flow doesn't have one.
1. Add one **Route Work** element:
   - Route a single record: `recordId`
   - Service Channel: **Phone**
   - Route To: **Agentforce Service Agent → Typeback Demo Voice**
   - Fallback queue: any queue (I used the contact center's default queue)
1. Save it as **Typeback Voice Routing**, then click **Activate**.

The built-in voice routing templates are managed and can't be retrieved to copy, so build this one from scratch. It's only one element.

**4.3 [HUMAN] Tie the number to the flow.** Go to **Setup → Agentforce Voice Setup → Voice Channels with Agents → New Channel**. Choose **PSTN Voice**, your number and **Typeback Voice Routing**, then click **Save**.

> [!WARNING]
> The channel is created **inactive**. Open the channel by clicking its name, then click **Activate**. The channel list has no toggle, and calls won't reach the agent until you do this.

**4.4 [AI] Check the routing:**

## What about texting the link by SMS?

Right now, the `Log` sender saves each link on its request row (`Test_Link__c`) instead of texting it, and `scripts/link.sh` prints it for you. I looked at two ways to send real texts. Neither is built yet.

- **Native SMS on the same number.** SMS is a separate messaging channel in Agentforce Contact Center (see "Create an SMS Channel in Agentforce Contact Center" in Salesforce Help). For a US 10-digit long code, you first register a 10DLC brand and campaign in **Setup → Messaging → Regulatory Compliance**. That's where I stopped: Register Brand said "You need an active brand license to register a brand." If your org has the license, the sending side would be the **Send Conversation Messages** action.
- **Twilio.** I confirmed the org can reach Twilio's API, but didn't build a sender. Keep in mind that a Twilio trial only texts verified numbers and adds a prefix to every message, toll-free numbers need verification before they can text US numbers, and US 10-digit numbers need A2P 10DLC registration.

To add a sender yourself:

1. Implement `TypebackSms.Sender` and return it from `TypebackSms.sender(name)`.
1. Let `scripts/configure.sh` accept its name.
1. Keep the callout before any DML, and put credentials in a named credential, never in code or settings.

## Troubleshooting: every problem I hit and the fix

"In the repo" means the fix is already in the scripts or code, so you'll only hit it if you change them.

### Salesforce CLI and project

| What happened | Why | Fix |
| --- | --- | --- |

Here's what I confirmed works in Agent Script on Summer '26, since the docs didn't say:

- `start_agent` can have an `actions:` block.
- Inside `instructions:->`, `run @actions.X with … set …` followed by a bare `transition to` works.
- `available when` accepts `and`, `not` and `!=`.
- `True` and `False` literals work in bindings, and boolean Apex outputs map to booleans.
- The `VoiceCallId: linked string` variable with `source: @VoiceCall.Id` compiles, and it's filled in on a real phone call.
- Preview with `--use-live-actions` runs the actions as the agent user.
